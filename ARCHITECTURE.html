Global Filter System

4-Filter Architecture: Time Period, Warehouse, Category, Order Status
All filters managed in useFilters composable and applied consistently across the application
  • Filter Changes: FilterBar component → useFilters composable → API query params
  • Data Fetching: Components import and call API client methods
  • State Management: Raw data in refs → Derived data in computed properties
  • Rendering: Computed properties watched by Vue template → DOM updates

Key Vue Patterns

State Management

  • useFilters composable: Global filter state
  • Component refs: Raw data (allOrders, inventoryItems)
  • Computed properties: Filtered/aggregated data
  • No Pinia/Vuex: Lightweight composable pattern

Component Patterns

  • Modal pattern: v-if visibility + props
  • Filter propagation: Global state → computed → display
  • API integration: Centralized api.js client
  • Unique v-for keys: sku, id, month (never index)

Key Architectural Patterns

1. Filter Propagation Pattern

Global filters affect all views consistently:

FilterBar
→
useFilters
→
API Query
→
Display

2. API Client Pattern

Centralized API client in api.js with consistent parameter construction using URLSearchParams

3. Computed Property Pattern

Raw data → Computed (filtered/aggregated) → Template rendering

4. Modal Pattern

Boolean ref controls visibility, props pass data, events close modal

5. Validation Pattern

Pydantic models on backend validate all input, frontend trusts API responses

Data Relationships

Order-Inventory Relationship: Orders contain items referenced by SKU to inventory master
Backlog-PurchaseOrder Relationship: Backlog items linked to purchase orders (1-to-many by backlog_item_id)
Dashboard Aggregations: Inventory value (qty × unit_cost), Low stock count (qty ≤ reorder_point), Pending orders sum

Data Characteristics

  • Order Date Range: January - September 2025
  • Warehouses: Tokyo, Dubai, San Francisco, and others
  • Categories: Circuit Boards, Sensors, Motors, Fasteners, Packaging, Composite Materials
  • Order Statuses: Delivered, Processing, Backordered
  • Order Volume: ~150KB JSON file with multiple items per order

Performance Characteristics

Current State (Demo)

  • ~170KB total data in memory
  • O(n) filtering per dimension
  • No pagination (full dataset returned)
  • Computed properties cached
  • All reads are instant

Scaling Considerations

  • Add database (PostgreSQL)
  • Implement pagination

  • Async database queries

Security & Deployment Notes

Current State (Local Development)

⚠️ Not Production-Ready:
  • No authentication/authorization
  • CORS allows all origins (*)
  • No rate limiting
  • No input validation beyond types
  • In-memory data (no persistence)
  • Suitable for local development only

For Production Deployment

  • Add authentication layer (JWT, OAuth)
  • Restrict CORS to specific origins
  • Implement rate limiting
  • Add comprehensive input validation
  • Use HTTPS only
  • Implement request/response logging
  • Add error tracking (Sentry, DataDog)
  • Database migration from JSON files
